## Success Criteria

A pillar is **≥95** when:

- **Code pillars** (L1, L4, L9–L13, L18, L19, L26, L28): full implementation + CI + 90% test coverage
- **Test pillars** (L21, L22): coverage gate ≥85%, all critical paths exercised
- **Process pillars** (L2, L3, L7, L20, L23, L30): docs + script + verified by new contributor
- **UX pillars** (L16, L17, L29): 5+ components/screens built, axe-clean, Lighthouse ≥95
- **Platform pillars** (L5, L8, L14, L24, L25, L27): full CI gates + scheduled runs + status badges
- **API pillars** (L15): OpenAPI spec + 5+ endpoints + auth
- **Release pillars** (L23): dist + attestations + checksums + cosign

1. Push `feat/audit-phase-2b` (AgilePlus) → 15 files, +1,260 lines
2. Push `main` (Planify) → 9 files, +474 lines
3. Create Phase A branch with cargo-fuzz + Vitest scaffolding
4. Create Phase B branch with proptest + a11y CI
5. Open PRs, get reviews, merge
6. Re-run audit, update scorecards

---

## Anti-Patterns to Avoid

1. **Don't add scaffolding without tests.** Every new feature needs tests in the same commit.
2. **Don't skip review.** Each phase should land as a PR with passing CI.
3. **Don't break the build.** Run `cargo check` and `bun run check` before every commit.
4. **Don't ignore warnings.** `-D warnings` is on; fix or document each one.
5. **Don't add docs without implementation.** Docs only count if the code they describe exists.
6. **Don't skip the audit.** Re-run the scorecard script after every phase to verify deltas.
