## 7. Audit scope recommendation (4 angles)

Each is a bounded audit that an isolated StaffSWE pane could land in ~30-60 minutes. They are independent and can run in parallel.

### 7.1. State audit — "what does the repo actually look like today?"
- Verify cargo workspace size on **local Mac** (cargo metadata + workspace member count vs PRD's "22").

- **One-line scope:** *"Refresh .cargo-test-result.txt, confirm 21-or-38-crate count, list PRs/head-distance deltas."*

### 7.2. Spec-impl gap audit — "what does the PRD claim vs what the code does?"
- Walk PRD epics E1-E12 against `crates/agileplus-domain` and `crates/agileplus-application` source.
- For each FR, classify: *implemented, partially-implemented, stubbed, missing*.
- Use the 92-case crosswalk as ground truth for "specified" rather than "implemented."
- Output a per-FR traceability matrix.
- **One-line scope:** *"PRD FRs × crates/agileplus-{domain,application,governance,import} implementation matrix."*

### 7.3. Integrations audit — "what's actually wired end-to-end?"
- **Plane.so:** Verify `crates/agileplus-plane` against a live or mocked Plane instance; check webhook signing, rate-limit handling, modules/cycles CRUD coverage, daemon process supervision.

### 7.4. Usability audit — "can a developer actually use it?"
